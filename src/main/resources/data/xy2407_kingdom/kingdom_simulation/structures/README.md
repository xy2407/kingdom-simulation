# 建筑蓝图资源目录

存放**随模组一起发布**的建筑蓝图，与玩家自己在游戏目录下放的蓝图共存。

## 目录结构

```
kingdom_simulation/structures/
├── residential/   住宅   提供床位
├── agriculture/   农业   提供岗位
├── livestock/     养殖   提供岗位
├── industry/      工业   提供岗位
├── commercial/    商业   提供岗位
└── military/      军事   提供岗位
```

目录名决定建筑的默认类型；同目录下的 `_example.json` 只是格式示例，没有同名 nbt 不会被识别。

## 命名规则

每个建筑由**同名的一对文件**组成：

```
residential/house_small.nbt    蓝图本体（Minecraft 结构文件）
residential/house_small.json   元数据（可省略）
```

- **标识**：相对 `structures` 的路径去掉扩展名，例如 `residential/house_small`。
  加载蓝图、网络传输、入库都用它，所以**不要在发布后重命名**。
- **json 可以省略**：省略时类型按所在目录推断，显示名用文件名，其余字段取默认值。
- **json 字段全部可选**，写错或读坏只会回落到默认值，不会让建筑列表失效。

## 元数据字段

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `name` | 字符串 | 文件名 | 列表卡片与悬停详情里显示的名字 |
| `type` | 字符串 | 按目录推断 | `RESIDENTIAL` / `AGRICULTURE` / `LIVESTOCK` / `INDUSTRY` / `COMMERCIAL` / `MILITARY`，也接受目录名与中文 |
| `tags` | 字符串数组 | 空 | 任意标签，二级分类也走这里 |
| `level` | 整数 | 1 | 建筑等级 |
| `jobs` | 整数 | 0 | 提供的岗位数，**非住宅类**使用 |
| `farm_slots` | 整数 | 0 | 种植格上限（**农业类**）：这座建筑最多能划出多少格农田 |
| `crops` | 数组 | 空 | 农业类能种的作物清单，见"农业"一节；留空则用服务端默认清单 |
| `animals` | 数组 | 空 | 养殖类能养的动物清单（面板上的配方），见"养殖"一节 |
| `nation` | 字符串 | 空 | 归属势力 |

**床位不在 json 里**。它是蓝图里画出来的客观属性，解析 nbt 时自动统计
（一张床由 `foot` / `head` 两个方块组成，只数 `foot`），**仅住宅类**使用。
想改床位数就直接改蓝图，不用改 json。

## 餐厅

市民饿了会去**商业类**建筑里的餐厅吃饭，判定条件（三者取"类型 + 二级分类"）：

- `type` 是 `COMMERCIAL`：写在 json 里，或把蓝图放在 `commercial/` 目录下由目录推断；
- `tags` 里带 `restaurant` / `dining` / `canteen` / `tavern` / `cafe` / `eatery`，
  或中文的 `餐厅` / `饭馆` / `餐馆` / `饭店` / `食堂` / `酒馆` / `小吃` 中任一词；
- 蓝图标识里带这些词也算（例如 `commercial/restaurant_small`）——只放 nbt、不写 json 时靠这条生效。

没有餐厅时市民就在自己周围找容器与地面掉落物里的食物；再找不到就原地停下挨饿，
等下一个觅食周期重新查一次城市表（城市建起餐厅后会自动改走餐厅）。

## 农业

农田面板的作物槽位来自**这座建筑的** json：

```json
"crops": [
  { "item": "minecraft:wheat", "name": "小麦" },
  "minecraft:carrot"
]
```

- 每项可以写对象（`item` 必填、`name` 可选）或直接写一个物品 id；
- `item` 既是面板槽位的图标，也是农夫决定种下哪个方块的依据；
- **不写 `crops` 就用服务端默认清单**：小麦、胡萝卜、马铃薯、甜菜根、南瓜、西瓜、
  火把花、瓶子草、甘蔗、甜浆果、竹子。

种下之后由打理人自动开垦与收获：

- 需要耕地的作物会先把泥土翻成耕地，并把这一格记进开垦表（之后永久湿润、不会退化成泥土）；
- 吃泥土的作物（甘蔗、甜浆果、竹子）**不翻耕**，能直接活就一直留在原土上；
- 收获按原版掉落表结算：产物先进打理人的行装（24 格），塞不下的掉在田里。

## 养殖

养殖面板"可养动物"里的每一条就是**一条配方**，来自**这座建筑的** json：

```json
"animals": [
  { "id": "cow", "name": "牛", "entity": "minecraft:cow",
    "capacity": 12, "feed": "minecraft:wheat", "mode": "collect", "output": "minecraft:milk_bucket" },
  { "id": "pig", "name": "猪", "entity": "minecraft:pig",
    "capacity": 8, "feed": "minecraft:carrot", "mode": "slaughter", "output": "minecraft:porkchop" }
]
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `id` | 字符串 | `entity` | 同一建筑内唯一，面板卡片与入库都用它 |
| `name` | 字符串 | `id` | 面板显示名 |
| `entity` | 字符串 | 无（**必填**，缺了整条丢弃） | 动物实体 id，如 `minecraft:cow` |
| `capacity` | 整数 | 24 | **这一栏的存栏上限**：写几就是几，只有不写才按 24 算 |
| `feed` | 字符串 | 空 | 饲料物品 id，投喂时从这座建筑的仓库里扣 |
| `mode` | 字符串 | `collect` | `collect` 采集（定期收奶/毛/蛋）或 `slaughter` 育肥宰杀 |
| `output` | 字符串 | 空 | 产出物品 id：采集型的出货、宰杀型的肉 |

面板上的玩法：

- 一级页点某一条进入**二级页**：上面是这条配方的详情（存栏 / 状态），下面是**饲养员名册**；
- 二级页点市民一行即**雇佣 / 解雇**，改动立刻生效、不用保存；「全部解雇」一键清空，名册上的"饥饿 / 下班"是这个人现在不能上工的原因；
- 回到一级页按「开始养殖」＝开始这一栏；同一座建筑同时只跑一条配方（开始新的一条会自动停下上一条），按钮随之变成「暂停养殖」；
- 缺饲料、没饲养员、建筑没了这些情况直接写在动物行的状态里，一眼能看出卡在哪；
- 上限、饲料、产出、产出方式**全部来自 json**，改完重启即生效，不用改代码。

## 当前状态

运行时蓝图仍从游戏目录的 `kingdom simulation/structures/` 读取。
本目录是随包发布用的**预留位置**，接上读取/部署逻辑之前，放在这里的文件不会生效。
